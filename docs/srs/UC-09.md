# UC-09 ช่างอัปเดตสถานะงานภาคสนาม (fully dressed)

ระบบ: บ้านพร้อม R1 | ผู้เขียน: กลุ่ม X (AI ร่างจาก brief ตอน /clarify ทีมตรวจ) | เวอร์ชัน: 1.0 (เข้า Baseline B2 ตาม CR-05) | ที่มา: EV-012, EV-019, EV-044

| หัวข้อ | รายละเอียด |
|---|---|
| Primary actor | ช่าง |
| Secondary actors | ลูกค้า (ดูสถานะ), เจ้าหน้าที่ call center (ดูสถานะเดียวกับลูกค้า), ระบบส่งข้อความ (IF-02) |
| Goal | ช่างบันทึกความคืบหน้าของงานจากหน้างานได้เอง และทุกฝ่ายเห็นสถานะเดียวกันโดยไม่ต้องโทรถาม |
| Precondition | มีงานสถานะ "ยืนยันแล้ว" ที่มอบหมายให้ช่างคนนี้ (จาก UC-07) การเข้าสู่ระบบของแอปช่างเลื่อนไป R2 ตัวอย่างใช้ช่างคงที่ |
| Postcondition (สำเร็จ) | งานมีสถานะใหม่ตามลูกศรของ MD-STM-01 มีแถวประวัติเพิ่ม 1 แถว ลูกค้าได้รับแจ้งภายใน 60 วินาที ลูกค้าและ call center เห็นสถานะใหม่ |
| Postcondition (ล้มเหลว) | สถานะงานไม่เปลี่ยน ไม่มีแถวประวัติใหม่ ไม่มีข้อความแจ้ง |
| Trigger | ช่างกดปุ่มเปลี่ยนสถานะบนรายการงานของตัวเอง |

## Main success scenario

1. ช่างเปิดรายการงานของตัวเอง ระบบแสดงเฉพาะงานของช่างคนนี้ พร้อมสถานะปัจจุบันและปุ่มที่กดได้ตาม BR-04 (เบอร์ลูกค้าแสดงเฉพาะช่วงที่ REQ-SEC-004 อนุญาต)
2. ช่างกดปุ่มสถานะถัดไป (ออกเดินทาง ถึงหน้างาน หรือ ปิดงาน)
3. ระบบตรวจว่างานเป็นของช่างคนนี้ และลูกศรนี้อยู่ใน BR-04
4. ระบบเปลี่ยนสถานะ บันทึกประวัติ (REQ-DAT-002) และวางข้อความแจ้งลูกค้าลงคิว (ภายใน 60 วินาที REQ-FN-053)
5. ระบบแสดงรายการงานพร้อมสถานะใหม่และปุ่มถัดไป ลูกค้าและ call center ที่เปิดดูสถานะเห็นค่าเดียวกัน (REQ-FN-052)

## Alternative flows

- A1 (หลังขั้น 4) ลูกค้าหรือเจ้าหน้าที่ call center เปิดดูสถานะงาน: กรอกหมายเลขงาน ระบบแสดงสถานะปัจจุบันและประวัติทุกแถวเรียงตามเวลา แล้วจบ use case

## Exception flows

- E1 (ขั้น 3) ลูกศรไม่อยู่ใน BR-04 (ข้ามขั้น ย้อนกลับ หรือเป็นลูกศรของ use case อื่น): ระบบปฏิเสธ แจ้ง "เปลี่ยนสถานะนี้ไม่ได้" สถานะเดิมคงอยู่ ไม่บันทึกประวัติ
- E2 (ขั้น 3) งานไม่ใช่ของช่างคนนี้: ระบบตอบว่าไม่พบงานของช่างคนนี้ ไม่เปลี่ยนอะไร
