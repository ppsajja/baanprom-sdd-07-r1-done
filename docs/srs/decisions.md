## 5. แผนรุ่น R1 และ R2 (ร่าง)

| รุ่น | use case | เหตุผล |
|---|---|---|
| R1 | UC-07 (รวม UC-03 ขั้น 2, UC-06 ขั้น 5, UC-10 ขั้น 6) | use case ที่เสี่ยงที่สุดและเป็นแกนของบริการ |
| R1 (เสนอ รอ SH-01 ยืนยัน) | UC-08, UC-09 | REQUIRES UC-07 ต้องมีงาน "ยืนยันแล้ว" ก่อน |
| R2 | UC-01, UC-02, UC-05, UC-11 | UC-02 ไม่ทันใน 8 สัปดาห์ (ใช้ลูกค้าคงที่เป็นทางชั่วคราว), UC-05 มีทางแก้ด้วยคน (call center), UC-11 ไม่มีหลักฐาน (CC-06) |
| ยังไม่กำหนด | UC-04, UC-12, UC-13 | ยังไม่มีข้อความ use case |

กำลังของรุ่นและสัดส่วน Must

```
กำลังของรุ่น     4 คน * 8 สัปดาห์              = 32 คน-สัปดาห์
R1              UC-07 14 + UC-09 5 + UC-08 6   = 25
สัดส่วน          25 / 32                        = 78 เปอร์เซ็นต์
คำแนะนำ DSDM     0.60 * 32                      = 19.2
เพิ่ม UC-02      25 + 8                          = 33 เกิน 32
```

แผนตึงเกินคำแนะนำ 60 เปอร์เซ็นต์ของ DSDM ทางถอยที่มีแล้วคือพฤติกรรมชั่วคราวของ Q-14 (ไม่อนุญาตให้ยกเลิกขณะช่างเดินทาง)
ทำลายความขึ้นต่อกันโดยตั้งใจ: UC-07 REQUIRES UC-02 แต่ UC-02 อยู่ R2 จึงใช้ลูกค้าคงที่ 1 คน และต้องมี UC-02 ก่อนขึ้นระบบจริง

## 6. DR-01 ช่องทางติดต่อระหว่างลูกค้ากับช่าง

สถานะ: ตัดสินแล้ว
เกี่ยวข้อง: EV-008, EV-003, EV-012, EV-017, EV-005 | รหัสร่าง REQ-018 ในทะเบียนหลักฐาน

บริบท:
- SH-01 ต้องการให้ลูกค้ากับช่างนัดแนะกันได้เร็ว (EV-008)
- SH-05 ต้องการไม่เปิดเผยเบอร์ส่วนตัวของช่างโดยไม่มีฐานทางกฎหมาย (EV-003)

ทางเลือก:
- A เปิดเบอร์ส่วนตัวของช่างให้ลูกค้า
- B ห้ามติดต่อตรง ทุกเรื่องผ่าน call center
- C โทรผ่านเบอร์กลางที่ซ่อนเบอร์จริง ใช้ได้เฉพาะงานที่นัดกันอยู่
- D แชตในแอปเท่านั้น

ทางที่เลือก: C
เหตุผล: นัดแนะได้เร็วเกือบเท่าโทรตรง และไม่มีใครเห็นเบอร์จริงของอีกฝั่ง

ทางที่ไม่เลือก:
- ไม่เลือก A: ขัดนโยบายข้อ 4.2 ตาม EV-003
- ไม่เลือก B: ช้า และเพิ่มสายเข้า call center ที่ล้นอยู่แล้ว (EV-012)
- ไม่เลือก D: สัญญาณบางหมู่บ้านหลุดบ่อย (EV-017) และช่างยังไม่ได้ใช้เครื่องมือในแอปเต็มที่ (EV-005)

ผู้ตัดสิน: SH-01 โดย SH-05 รับรองว่าทางเลือก C ไม่ขัดนโยบายข้อ 4.2

ผลที่ตามมา:
- เพิ่มค่าบริการเบอร์กลาง ซึ่ง SH-01 ยอมรับ
- ต้องเขียนความต้องการเพิ่มในหมวดการเชื่อมต่อและความเป็นส่วนตัว
- รหัสร่าง REQ-018 ต้องตั้งรหัสใหม่ตามหมวดก่อนเข้า catalogue (ยังไม่ออกเลข)

ทบทวนใหม่เมื่อ:
- ค่าบริการเบอร์กลางเกินงบของรุ่น
- นโยบายข้อ 4.2 เปลี่ยน
- สายถามสถานะที่ call center ไม่ลดลง

## 7. DR-02 ยอดคืนมัดจำเมื่อลูกค้ายกเลิกขณะช่างกำลังเดินทาง (BR-01 แถว R3)

สถานะ: อนุมัติ (accepted) ทางเลือก D โดย SH-01 ในประชุม EV-048 (CR-10) สถานะเดิม: เสนอ (proposed) รอ SH-01 อนุมัติ
วันที่: 3 พ.ย. 2569 (Finance ยืนยันค่าเดินทางเหมา 100 บาทจากค่าเดินทางเฉลี่ย 3 เดือน)
ผู้ตัดสิน: SH-01 เจ้าของธุรกิจ
ผู้ถูกปรึกษา: ตัวแทนช่าง, call center, Finance, RE lead
ผู้ต้องรู้: Dev lead, ผู้ทดสอบ
เกี่ยวข้อง: BR-01 R3, Q-14, REQ-BR-001, AC-07-10, UC-08

### บริบทและปัญหา

BR-01 แถว R3 ยังไม่มียอดคืน (รอ Q-14) ระหว่างนี้ใช้พฤติกรรมชั่วคราวของ Q-14
ลูกค้ายกเลิกไม่ได้ ต้องโทรหา call center ทุกกรณี

### ตารางจุดยืนกับ win condition [การจำลองเพื่อการสอน]

| ฝ่าย | จุดยืน | Win condition | BATNA |
|---|---|---|---|
| ลูกค้า | ขอคืนเต็ม | เห็นยอดคืนก่อนกด และได้คืนส่วนใหญ่ | โทรหา call center แล้วร้องเรียน |
| ช่าง | ค่าน้ำมันใครจ่าย | ไม่เสียค่าเดินทางฟรี | ปฏิเสธงานช่วงที่เสี่ยงถูกยกเลิก |
| call center | อย่าให้ทุกเคสโทรมาหาเรา | กฎชัด ลูกค้าทำเองบนจอได้ | รับสายทุกกรณีต่อไป |
| SH-01 เจ้าของ | ไม่อยากเสียทั้งลูกค้าและช่าง | กติกาเป็นธรรม ใช้ได้กับทุกงาน | คงพฤติกรรมชั่วคราวไว้ แล้วรับความเสี่ยงเรื่องข้อร้องเรียน |

### ปัจจัยที่ใช้ตัดสิน

- ลูกค้าเห็นยอดคืนก่อนกดยืนยัน
- ช่างไม่เสียค่าเดินทางฟรี
- กฎเป็นตาราง ไม่ใช่ดุลยพินิจรายกรณี
- คืนผ่าน Payment Gateway รายเดิม (REQ-CON-003, REQ-IF-001)

### ทางเลือกที่พิจารณา (มัดจำตัวอย่าง 350 บาท)

| ทางเลือก | คืนลูกค้า |
|---|---|
| A ไม่คืนเลย | 0 บาท |
| B คืนเต็ม | 350 บาท |
| C คืนครึ่ง ปัดขึ้นหลักสิบ เหมือน R2 | 180 บาท |
| D หักค่าเดินทางเหมาให้ช่าง คืนส่วนที่เหลือ | 250 บาท (ค่าเดินทางเหมา 100 บาทเป็นตัวเลขสมมติ) |
| E คงพฤติกรรมชั่วคราว (ทางสำรองร่วม) | ยกเลิกไม่ได้ |

### ผลการตัดสิน (เสนอ)

เลือก D เพราะเป็นทางเดียวที่ตอบ win condition ของลูกค้า ช่าง และ call center พร้อมกัน
ค่าเดินทางเหมาใช้ค่าตัวอย่าง 100 บาท รอข้อมูลค่าเดินทางจริงจาก Finance

ผลที่ตามมา:
- ดี: ลูกค้ายกเลิกเองได้และเห็นยอดก่อน สายเข้า call center กรณีนี้ลดลง
- เสีย: ต้องแก้ BR-01 แถว R3 (ผู้อนุมัติ SH-01) ถ้าอนุมัติหลัง Baseline B1 ต้องเปิด CR
- เสีย: ต้องเพิ่มตัวอย่างแถว R3 ใน AC-07-10 และจ่ายส่วนของช่างแยก

การยืนยันผล:
- ตัวอย่างแถว R3 ใน AC-07-10 มียอดคืนที่ตรวจได้ และ test ของแถวนี้ไม่ถูกข้าม
- นับสายที่ call center เรื่องยกเลิกขณะช่างเดินทาง ก่อนและหลังใช้กฎใหม่

### ข้อดีข้อเสียของแต่ละทาง

- A ช่างได้ แต่ลูกค้าเสียทั้งหมด เสี่ยงข้อร้องเรียน
- B ลูกค้าได้ แต่ช่างเสียค่าเดินทางฟรี
- C ใช้สูตรเดิมของ R2 ง่าย แต่ไม่บอกว่าส่วนที่หักไปถึงช่าง
- E ไม่ต้องทำอะไร แต่ call center รับสายทุกกรณี และ Q-14 ค้างต่อ

### ทบทวนใหม่เมื่อ

- ค่าเดินทางจริงต่างจาก 100 บาทมาก
- ช่างร้องเรียนว่าค่าเหมาไม่พอ หรือลูกค้าร้องเรียนว่าหักมากไป
- มีการแก้ BR-01 แถวอื่น
