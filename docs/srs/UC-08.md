# UC-08 ลูกค้ายกเลิกการจองและรับเงินคืน (fully dressed)

ระบบ: บ้านพร้อม R1 | ผู้เขียน: กลุ่ม X (AI ร่างตอน /clarify ทีมตรวจ) | เวอร์ชัน: 1.0 (เข้า Baseline B2 ตาม CR-06) | ที่มา: EV-023, EV-012, EV-044
หมายเหตุรหัส: UC-08 คือการยกเลิกการจองและรับเงินคืนเท่านั้น UC-07.md เส้นทาง A1 เคยเรียก waitlist ว่า UC-08 แก้แล้ว (คิวรอยังไม่มีรหัส UC ดู Q-33)

| หัวข้อ | รายละเอียด |
|---|---|
| Primary actor | ลูกค้าที่ลงทะเบียนแล้ว |
| Secondary actors | ช่าง (ได้รับแจ้ง ช่วงเวลากลับเป็นว่าง), Payment Gateway (IF-01 คืนเงิน), ระบบส่งข้อความ (IF-02) |
| Goal | ลูกค้ายกเลิกงานของตัวเองได้เองตามนโยบาย BR-01 เห็นยอดคืนก่อนตัดสินใจ และได้เงินคืนผ่านช่องทางที่ชำระ |
| Precondition | มีงานของลูกค้าคนนี้ที่ชำระมัดจำสำเร็จแล้ว (สถานะ "ยืนยันแล้ว" จาก UC-07) การเข้าสู่ระบบ (UC-02) เลื่อนไป R2 ตัวอย่างใช้ลูกค้าคงที่ |
| Postcondition (สำเร็จ) | งานมีสถานะ "ยกเลิก" พร้อมแถวประวัติ ช่วงเวลาของช่างเป็น "ว่าง" มีรายการคืนเงิน 1 รายการที่ส่งคำขอไป Payment Gateway แล้วด้วย reference ของการชำระเดิม ลูกค้าและช่างได้รับแจ้งภายใน 60 วินาที |
| Postcondition (ล้มเหลว) | สถานะงานไม่เปลี่ยน ไม่มีรายการคืนเงิน ไม่มีคำขอไป gateway |
| Trigger | ลูกค้ากด "ดูเงื่อนไขการยกเลิก" ของงานตัวเอง |

## Main success scenario

1. ลูกค้ากรอกหมายเลขงานและขอดูเงื่อนไขการยกเลิก
2. ระบบตรวจว่าเป็นงานของลูกค้าคนนี้ แล้วแสดงสถานะ เวลานัด มัดจำที่ชำระแล้ว และยอดคืนตาม BR-01 ณ เวลานี้ (R1 หรือ R2)
3. ลูกค้ากดยืนยันยกเลิกและรับเงินคืน
4. ระบบคิดยอดคืนใหม่ ณ เวลาที่กด (AS-13) เปลี่ยนสถานะงานเป็น "ยกเลิก" บันทึกประวัติ และปล่อยช่วงเวลาให้ "ว่าง" (BR-05 ขั้น 1 ถึง 2)
5. ระบบส่งคำขอคืนเงินผ่าน Payment Gateway รายเดิม ด้วย reference ของการชำระมัดจำ ยอดตาม BR-01 ครั้งเดียว และบันทึกผล (BR-05 ขั้น 3)
6. ระบบแจ้งลูกค้า (พร้อมยอดคืน) และช่างภายใน 60 วินาที แล้วแสดงหน้าผลการยกเลิกพร้อมยอดคืนจริง

## Alternative flows

- A1 (ขั้น 2) BR-01 ไม่อนุญาตให้ยกเลิก (R6 กำลังดำเนินงานหรือเสร็จสิ้น CR-10: R3 ช่างกำลังเดินทาง ย้ายไปเส้นทางหลัก ยอดคืนหักค่าเดินทางของช่าง AC-08-12): ระบบแสดง "ยกเลิกไม่ได้" พร้อมข้อความของแถวนั้น ไม่มีปุ่มยืนยัน แล้วจบ use case

## Exception flows

- E1 (ขั้น 5) Payment Gateway ปฏิเสธหรือไม่ตอบคำขอคืนเงิน: ระบบบันทึกผลที่ได้ลงรายการคืนเงิน งานยังคงเป็น "ยกเลิก" ไม่ส่งซ้ำเอง (CR-10 Q-34 ปิด: ลูกค้าเห็นว่าต้องตรวจสอบเพิ่ม Finance ปิดรายการภายใน 1 วันทำการ AC-08-11)
- E2 (ขั้น 3) งานถูกยกเลิกไปแล้ว (ลูกค้ากดซ้ำหรือระบบยกเลิกไปก่อน): ระบบปฏิเสธ แจ้งว่างานนี้ถูกยกเลิกไปแล้ว และไม่ส่งคำขอคืนเงินซ้ำ
