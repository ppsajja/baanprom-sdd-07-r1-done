ที่มา: บทเสริม การตรวจรับและการส่งมอบ หัวข้อ 8.2 (แผน OAT ของ R1) ใช้วิธีตรวจในหัวข้อ "ตรวจอย่างไร" ของข้อกำหนดส่วน 6 ในไฟล์กลางทุกข้อ ไม่คิดวิธีตรวจใหม่
ข้อต่างจากตัวอย่างในหน้าบทเรียน: ตัวอย่างเขียนว่า "ร่าง ใช้ได้เมื่อ CR-07 อนุมัติ" เพราะตอนนั้น CR-07 ยังเป็น Proposed ใน repo นี้ CR-07 อนุมัติแล้วตั้งแต่ B3 (EV-045) แผนนี้จึงใช้ตัดสินรับได้จริง

คนที่รับภาระดูแลระบบ คือคนที่ตัดสินรับด้านนี้ SH-01 รับทราบ เพราะการตัดสินเรื่องเงินและลูกค้ายังเป็นของเจ้าของ

## สภาพแวดล้อม

เครื่องทดสอบเครื่องเดียวกับ UAT ตั้งค่าเหมือนระบบจริง: APP_ENV=production, PostgreSQL 16 (D-00-02), OPS_TOKEN ของเครื่องทดสอบ, ERASURE_LEDGER_PATH และ BACKUP_DIR อยู่นอกโฟลเดอร์ของโปรแกรม
ระบบภายนอกยังเป็นตัวจำลอง (FakeGateway, FakeNotifier) ตั้งพฤติกรรมของ gateway จำลองผ่านตัวแปร FAKE_GATEWAY_MODE, FAKE_GATEWAY_INQUIRY, FAKE_GATEWAY_REFUND_MODE (มีเฉพาะเครื่องทดสอบ) เครื่องรับข้อความเวรเป็นเครื่องรับ webhook ทดสอบ แทนบริการจริงที่ Ops lead เลือก (EV-048)

## เกณฑ์เริ่ม

- เกณฑ์เริ่มของ UAT ผ่านแล้ว (uat-plan-r1.md ส่วน 6)
- Q-40, Q-43, Q-44 มีคำตอบแล้ว (ปิดใน EV-045) ตัวเลขทุกตัวในแผนนี้มีผู้ยืนยัน
- คู่มือรับมือเหตุรุ่น 1.2 และบัญชี endpoint ตรงกับ commit ที่ส่งตรวจ

## เกณฑ์จบ

OAT-1 ถึง OAT-7 ผ่านทุกข้อ ข้อที่ทำได้เพียงบางส่วนบนเครื่องทดสอบ (เช่น ระบบภายนอกยังเป็นตัวจำลอง) เขียนเป็นเงื่อนไขของการขึ้นระบบจริง ไม่นับว่าผ่าน

## ไม่ใช่เกณฑ์ของรอบนี้

- REQ-OP-001 (นาทีล่มรวมรายเดือน) วัดได้หลังใช้งานจริง ใส่เป็นเงื่อนไขของช่วง hypercare
- ซ้อมกู้คืนบนเครื่องจริงของระบบที่ใช้งาน (เครื่องจริงยังไม่มี) ทำครั้งแรกในวันติดตั้งจริง ตามรายการส่งมอบ
- บริการส่งข้อความ gateway และ LLM ตัวจริง ยังไม่ต่อ (รายการของจำลองใน docs/handover/)
